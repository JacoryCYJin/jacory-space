# Minecraft Skin 模型状态与 PNG 导出流程

状态：已实现  
目标仓库：`site/jacory-space-frontend`  
关联服务：`minecraft-studio-service/services/block-skin-generation`

## 1. 目的

Classic 和 Slim 的差异既关系到 3D 人物的手臂宽度，也关系到 PNG 的手臂 UV
布局。编辑器将“当前查看的模型”和“画布 PNG 的实际格式”分开保存，避免用户仅
切换预览时意外改写、裁剪或错误导出皮肤。

用户始终只有一个下载入口：编辑器右下角的「导出皮肤」。BLOCK 服务保存的
`skin.png` 是前端读取生成结果的内部中间文件，不是第二个用户导出入口。

## 2. 两个模型状态

| 状态 | 含义 | 用途 | 是否会改写画布 |
| --- | --- | --- | --- |
| `previewModel` | 当前 3D 预览模型 | 决定宽手臂或细手臂预览；作为下一次 AI 请求的目标模型 | 否 |
| `skinModel` | 当前画布 PNG 的实际格式 | 决定导出时使用 Classic 或 Slim 规范化规则；随撤销/恢复保存 | 否，除 AI/导入写入新画布时更新状态 |

因此，将一张 Classic 皮肤临时切到 Slim 查看，只会改变 3D 人物；不会删除其
Classic 手臂像素，也不会把它的实际格式改成 Slim。

## 3. 导入识别

导入 PNG 时，编辑器先将图片规范化为 64×64，再检查 Java Slim 手臂中不使用的
四个 UV 区域：

| 区域 | 坐标（左上至右下） |
| --- | --- |
| 右臂顶部／底部闲置位 | `(50,16)`–`(52,20)` |
| 右臂正面／背面闲置位 | `(54,20)`–`(56,32)` |
| 左臂顶部／底部闲置位 | `(42,48)`–`(44,52)` |
| 左臂正面／背面闲置位 | `(46,52)`–`(48,64)` |

任一区域含透明像素，或四个区域同时全黑／全白时，识别为 Slim；否则识别为
Classic。识别结果写入 `skinModel`，并作为导入后的初始 `previewModel`。旧的本地
项目恢复时也会重新从画布 PNG 推断 `skinModel`，不沿用旧版本仅用于预览的模型值。

## 4. 预览与编辑

1. 用户点击 Classic / Slim 切换时，只修改 `previewModel`。
2. 3D 预览据此选择宽手臂或细手臂几何体。
3. 像素画布、撤销历史与 `skinModel` 不受影响。
4. 新建皮肤默认 `previewModel = classic`、`skinModel = classic`。

不提供在模型切换时自动执行 Slim → Classic 转换。该方向需要补出原图不存在的
纹理列，不能静默处理；如以后需要，应设计为独立且明确的转换操作。

## 5. AI 生成与 BLOCK

AI 请求使用 `previewModel`：默认是 Classic；只有用户明确选择 Slim，才请求 Slim
结果。接口返回的 `model` 必须与请求模型一致，前端才会将候选图自动写入编辑器
画布。写入后：

1. 返回模型写入 `skinModel`；
2. 预览同步到该模型；
3. 原画布和其 `skinModel` 一同进入撤销历史。

BLOCK 服务保持其独立的临时产物流程：

`角色双视角预览 → BLOCK 临时 skin.png → 前端自动写入编辑器画布`

BLOCK 默认使用 Classic 基础提示。只有 `model=slim` 时才附加 Java Slim 3 像素手臂
UV 要求，并清空 64 个 Slim 闲置 UV 像素。这样临时 PNG 本身也能在之后被正确识别
为 Slim；它不会提供额外的用户下载入口。

## 6. 唯一导出流程

用户点击「导出皮肤」后，编辑器创建当前画布的下载副本，再按照 `skinModel` 处理：

| `skinModel` | 下载副本处理 | 对编辑器画布的影响 |
| --- | --- | --- |
| `classic` | 原样导出；保留所有 Classic 手臂 UV 像素 | 无 |
| `slim` | 仅清空 4 块 Slim 闲置位（共 64 像素），确保再次导入可识别为 Slim | 无 |

这意味着：一张实际为 Classic 的皮肤即使正以 Slim 方式预览，导出时仍会完整保留
Classic 图；只有 `skinModel = slim` 的皮肤才会在下载副本中清理 Slim 闲置位。

导出不依赖后端。后端未启动时，用户仍可导出当前已导入、新建或已经应用到画布的
皮肤；后端只影响是否能够生成新的 AI 结果。

## 7. 验收要点

- 导入符合 Slim 闲置位规则的 PNG 后，预览自动切为 Slim。
- Classic PNG 切换 Slim 预览再导出，源画布与下载图都保留 Classic 额外手臂像素。
- BLOCK 明确生成 Slim 后，应用到画布并导出；再次导入时应识别为 Slim。
- 模型预览切换不产生像素编辑历史，也不改变 `skinModel`。
- 整个界面只存在编辑器的一个「导出皮肤」用户入口。
